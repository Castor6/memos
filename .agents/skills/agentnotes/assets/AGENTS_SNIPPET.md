## Task notes

- Use the `agentnotes` skill to preserve substantive requirements, design
  decisions and their reasons, and implementation outcomes in `docs/tasks/`.
  Use `TASK-YYYYMMDD-short-topic.md` with `TEMPLATE.md`; continue the same task
  in its original file. Related small fixes can share a record.
- Keep dated facts, actual verification, and uncovered scope. Use the user's
  requested language or this project's documentation language. Keep one
  maintainer per note and link independent related work.
- Search relevant notes when continuing work or recalling a decision.
  `INDEX.md` is a fixed search guide; do not maintain a shared task list or
  load the entire history at startup.
