# ZIP 笔记迁移格式

2026-09-22 引入上游 v0.31.0 的 Memos Export Format 1.0 读写器，来源提交为
`2b2192d4e153bd04f1d325b60fd880cf00d68b01`，原文件位于 `core/memoexport/`，
本仓库适配为 `internal/memoexport/`。原始格式说明见
[上游设计文档](https://github.com/usememos/memos/blob/v0.31.0/docs/design/memos-export-format.md)。

## 范围与入口

设置 → 导入与导出可以导出当前账号在全部个人空间的笔记、待办、归档、本人评论及其关联附件。
包含正文、独立标签、位置、创建/更新时间、置顶、归档状态、同账号引用和附件原始字节。
不包括其他用户的笔记、未关联笔记的附件、分享授权、账号密码、令牌、系统设置、微信队列或部署配置，
不能代替服务器完整备份。

归档中的其他用户评论不在导出范围；本人评论的原笔记不在归档时，导出为私有独立笔记并给出提示。
外部附件保留 HTTP(S) 链接并提示不含远端文件；本地、数据库与 S3 附件保存实际文件和 SHA-256。
导出时任何应包含的本地/S3文件读取失败都会报错，不生成缺少该附件的成功结果。
反应记录不包含在本次导出和恢复范围，导入包含反应的上游归档时会提示。

RPC 为 `MemoTransferService.ExportMemoArchive` 与 `ImportMemoArchive`，
HTTP 对应 `POST /api/v1/memoArchive:export` 和 `POST /api/v1/memoArchive:import`。
两条路由均要求登录，导出范围固定为当前账号，不接受目标用户参数。

## 容器与扩展

- `manifest.json` 标识 `memos-export`、版本 `1.0`、导出账号、时间与计数。
- `memos/<uid>.json` 保存元数据；`memos/<uid>.md` 保存 UTF-8 原文。
- `attachments/<uid>/<safe-filename>` 保存文件；记录包含文件长度与 SHA-256。
- 清单的 `castor: { version: 1, spaces: { id: name } }` 保存个人空间，包括空空间。
- 笔记的 `castor: { version: 1, space, isTodo, explicitTags }` 保存定制语义。
- 附件的 `castorMotionMedia` 保存本项目动态照片的 Proto JSON 元数据；Android 动态照片恢复时检查实际文件。

未知普通 JSON 字段按上游格式允许忽略。本项目扩展版本不支持时明确拒绝，避免默默丢失定制信息。
原版上游归档没有本项目扩展，其笔记放入导入时选择的个人空间；
上游 `SPACE` 可见性降为私有并提示，不把协作空间权限映射为本地个人空间权限。
普通上游标签按独立标签导入，避免被正文解析重新改写。

## 校验、冲突与失败

单 ZIP 最多 128 MiB，展开条目及逻辑恢复数据分别最多 512 MiB，
最多 10,000 条笔记和 100,000 个 ZIP 条目；单附件仍受当前实例上传大小限制。
正文仍受实例正文长度限制。每实例同时运行一个迁移操作，单次最多 5 分钟。
ZIP 路径、重复条目、格式、版本、长度、校验和、正文、标签和个人空间均先校验后写入。
附件使用 ZIP Store，保证高压缩率文件不会生成自身读写器拒绝的归档。

已有笔记 UID 一律跳过，不修改现有正文、状态、附件或引用。
附件 UID 冲突时生成新 UID 并重写正文中的本地附件路径。
同 ID 不同名称的个人空间不会覆盖原名称；导入内容放到新空间，全部笔记已存在时不再增加空间。
缺失、跨个人空间或不符合待办规则的引用会提示并跳过，不读取或绑定无权内容。

新笔记首先保持私有，完成关系后一起恢复最终可见性与归档状态，防止公开归档被暂时公开。
创建后立即记录本次新增记录；写入或最终还原失败会尝试回滚本次新增笔记及附件，并在返回结果中报告错误。
回滚不删除已有笔记；回滚自身失败时明确提示需检查残留再重试。新增空空间可能保留。
整个导入不发送 Webhook 或提及通知，成功后只通知当前账号刷新。
导入恢复已校验的附件原始字节，不对 JPEG 再次有损重编码。
