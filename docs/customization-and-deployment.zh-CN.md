## 仓库与分支约定

目标是维护自己的 Memos 版本，按需要吸收上游修复和功能，目前不以向上游提交修改为目标。

| 名称 | 用途 |
| --- | --- |
| `main` | 自己的定制主分支 |
| `origin` | 自己的 GitHub Fork：`Castor6/memos` |
| `upstream` | 官方仓库：`usememos/memos` |
| `upstream/main` | 最近一次获取的上游主分支状态，由 Git 维护 |

无需额外长期维护 `custom` 或纯官方本地分支。通过 `git fetch upstream` 获取更新，再查看差异，决定是否引入。
获取上游代码本身不会修改自己的 `main`。

- 独立修复可以通过 `cherry-pick` 引入；新功能可能依赖多个提交或数据库迁移，需要一起评估。
- 跟进完整版本时，在临时分支合并上游版本并测试，通过 PR 合入自己的 `main`。
- 个人定制、修复、文档和基础设施更新均使用目的明确的分支，通过 PR 合入 `main`。
- 本地 Git 默认推送目标和 GitHub CLI 默认仓库均设置为自己的 Fork。

## 自动部署方案

优先评估以下方式：

1. 日常更新通过 PR 接受 CI 检查；可发布改动合入自己的 `main` 后，机器人持续更新同一个版本 PR。
2. 合并版本 PR 是正式发布入口，由 GitHub Actions 对该版本对应的确定提交执行检查并构建带版本标记的容器镜像。
3. 将镜像推送到国内镜像仓库，候选为阿里云 ACR。
4. 服务器主动定时检查指定发布通道，拉取已发布的镜像并按摘要固定版本。
5. 镜像下载和校验完成后，执行本机部署脚本，完成备份、更新和运行检查。

发布通道只在构建、测试和镜像推送全部成功后更新。服务器检查仓库中的发布状态即可，不要求访问 GitHub。
镜像摘要用于确认具体部署内容；发布权限只授予可信工作流，服务器持有拉取所需的最小权限。

这套方式可以让 GitHub 构建工作流不需要服务器地址或 SSH 私钥，也无需经过开发者电脑中转。
构建由 GitHub 执行，服务器负责拉取和运行。GitHub 向国内仓库推送仍可能受跨境网络影响，需要超时、重试和失败处理。

### 发布与恢复要求

- 正式版本发布是预期的上线触发点；日常提交主要触发检查。
- 新镜像下载失败时，线上旧版本继续运行，不进入停机更新阶段。
- 更新前正常停止应用，完整备份数据库、附件及运行配置，并校验备份；备份失败则终止更新并恢复原服务。
- SQLite 的数据库文件、WAL 等必须保持一致，不直接复制运行中的单个 `.db` 文件作为完整备份。
- 更新任务串行执行，防止两个版本同时部署；保留上一个镜像、配置和对应数据备份。
- 检查应用启动、登录、笔记及附件访问。部署日志保留在受控位置，不写入公开构建日志。
- 数据库发生迁移时，不能假定换回旧镜像即可恢复；需确认数据兼容性及恢复步骤，避免覆盖更新后的新笔记。
- 服务器上的更新前备份不等于异地备份。自动异地备份和证书续签需要另行配置。

以上均是待实现的要求，不代表当前已具备这些能力。

## 阿里云 ACR：已确认的支持与费用

### GitHub Actions 能否推送到国内 ACR

可以。阿里云官方 `aliyun/acr-login` 仓库提供了 GitHub Actions 构建镜像、登录并推送到杭州地域 ACR 的示例。
国内地域本身不阻止这种接入方式；实际使用需要正确的仓库地址、认证和网络访问配置。

官方 FAQ 同时说明，从海外构建环境向中国内地推送镜像可能遇到网络问题。
目前确认的是官方支持这种接入方式，尚未对本 Fork、实际 ACR 实例和目标服务器做端到端测试。
官方示例用于确认能力，实施时还需核对当前 Action 版本和新个人版实例的实际接入域名。

### 费用与限制

| 版本 | 已核实的计费方式 | 选型限制 |
| --- | --- | --- |
| ACR 个人版 | 当前公测限额免费，镜像上传和拉取免费 | 仅限开发测试，无可用性保障及相关赔偿 |
| ACR 企业版（含经济版） | 包年包月实例费，另可能产生 OSS 存储、公网流出流量及选配服务费用 | 金额取决于地域、规格、购买时长和选配项，以实际购买页为准 |

个人版创建条件：

- 账号必须完成个人类型实名认证。
- 自 2024-09-09 起，单个账号最多创建一个个人版实例；已有一个或更多实例时不能再新建。
- 可创建地域以控制台为准；若可选，优先评估与服务器同地域的仓库及内网拉取方式。
- 官方将免费个人版限制为开发测试用途，不能仅凭“个人使用”就认定它适合长期正式运行的服务。

结论：可先用免费个人版验证开发测试链路，再根据用途限制及实际报价确定长期发布方案。
尚未核对本账号的 ACR 创建资格、已有实例或企业版报价，也未购买服务。ACR 企业版付费并不保证 GitHub 到仓库的跨境连接一定稳定。
这里的免费说明仅针对 ACR 个人版，不代表 GitHub Actions、服务器等整条链路的费用均为零。

## 公开仓库与部署隐私

- 代码和通用部署模板可以公开；真实服务器 IP、连接配置、SSH 私钥、账号密码、证书私钥、笔记和备份保持在仓库之外。
- 本仓库是独立的源码目录，不将原维护目录或其 Git 历史整体导入。
- 镜像只包含应用及所需运行文件，不打包真实运行配置、笔记、附件和凭据。
- 采用服务器主动拉取方案时，GitHub 只需镜像发布权限，不需要服务器管理权限。
- 仓库访问凭据使用 Actions Secrets 等受控存储，并检查日志；自动遮罩不是绝对保证，不主动输出凭据或敏感配置。
- 公网地址本身仍可能被扫描发现；这里避免公开的是本项目与实际部署地址的关联。
- 若改用 SSH 推送部署，使用独立且权限受限的部署凭据，保持服务器主机身份校验，不复用本机管理员私钥。
