# 链接预览的缓存与后台处理

链接预览按 URL 保存首次成功取得的标题、摘要和图片快照。成功后永久复用，不设置 TTL，不因刷新页面、重启、编辑正文或其他笔记引用同一链接而重新抓取，也不自动更新历史标题和摘要。

前端优先显示笔记附带的成功快照。尚未取得有效标题时保持普通链接；链接接近视口后可以请求预览，成功后才切换成卡片。单次请求失败不在浏览器立即重试；重新打开笔记、窗口聚焦或网络重连仍可能再次请求 Memos 接口，后端退避期内不会重新抓取目标网站。

## 持久状态

- `link_metadata` 保存成功快照，重复写入不覆盖。
- `link_metadata_job` 保存尚未成功的 URL、尝试次数、下次尝试时间和领取租约。笔记新增、正文修改与任务登记在同一数据库事务中完成。
- `link_metadata_backfill` 保存历史笔记的上界和游标。按 ID 每批扫描 100 条，进度与入队一起提交；完成后不再扫描笔记表。新增和编辑走事务入队，不依赖反复全库扫描。

接口和后台共享任务领取逻辑。同一 URL 的有效租约内只允许一个抓取者；领取使用数据库条件更新，成功提交校验领取令牌，过期工作者不能覆盖结果。正常抓取超时 45 秒，租约 90 秒；异常退出后的未完成任务可被重新领取。因此这里保证成功快照不重复抓取，但不承诺进程崩溃等情况下外部 HTTP 请求恰好执行一次。

后台每 5 秒触发一轮，每轮最多处理 8 个待执行 URL。失败从 1 分钟开始指数退避，最大间隔 24 小时，仍保留后续重试机会；8 个是每轮工作预算，不是单个 URL 的重试次数限制。没有有效标题的响应不算成功。无效协议、无主机或明确不允许的字面地址不会进入队列；网络解析及连接仍由安全 HTTP 客户端检查。

仅通过预览接口请求、尚未由笔记登记的 URL 使用同一租约协调，但失败任务只保留固定 15 分钟，不由后台自动抓取；再次调用接口也不延长该窗口。后台按索引每批回收最多 100 个到期且无有效租约的临时任务。笔记新增、修改或历史回填可将同 URL 原子提升为持续后台任务，保留已有租约和退避时间；后续接口请求不会降级它。这里的到期只针对未成功的临时任务，成功快照仍永久保留。

相关实现位于 `store/link_metadata*.go`、`server/runner/linkmetadata/` 和 `server/router/api/v1/memo_service_link_metadata.go`。表结构变化须同时维护 SQLite、MySQL、PostgreSQL 的增量迁移和 `LATEST.sql`。
