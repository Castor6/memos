# 内置微信客服：已选方案与迁移边界

决策日期：2026-09-19。用户选择将已有微信客服能力改为 Memos Go 后端内置模块。本文定义目标与验收范围。2026-09-19 已实现第一阶段 Go 协议、消息转换和内部保存核心；尚未接入运行路由或后台任务。实施记录见[主任务](tasks/TASK-20260919-wechat-kf-integration.md)。

## 产品目标

本人主动发送或转发内容到微信客服，直接保存为自己的私有 Memos。由 Memos 提供可启停的接入模块、配置与处理结果入口。代码、任务、测试和版本在一个项目内维护，随同一 Memos 镜像部署。

已有 Python 服务位于 ~/Code/wechat-kf-memos，现有 0.1.2 的功能、测试和真实验收是迁移参照；把该目录复制进仓库或在容器内同时启动 Python 进程，不构成本方案的完成。

## 实现方向

| 部分 | 内置方案 |
| --- | --- |
| 微信协议 | 独立 Go 模块负责 API 客户端、签名/AES 校验、消息解析；保留腾讯官方测试向量 |
| 回调与后台处理 | 由 Memos 路由接收回调，先持久化再应答；后台任务随应用启动/停止，网络调用与普通笔记请求分离 |
| 保存笔记及附件 | 提炼或复用 Memos 业务逻辑，明确绑定用户和个人空间；沿用权限、标签、长度检查、附件归属和通知行为 |
| 身份与配置 | 微信发送者白名单对应明确的 Memos 用户；默认关闭，仅授权管理入口可配置，密钥不明文回显或进入日志 |
| 运行状态 | 游标、任务、去重、事件、回执通过 Memos store 的专用结构持久化，支持三驱动迁移；成功正文清理，失败保留必要恢复信息 |
| 设置界面 | 提供接入开关、配置、本人绑定、默认标签和处理结果；遵循 Memos 已有桌面/手机设置风格 |
| 构建发布 | Go 模块进入既有 Memos 构建和版本流程，GitHub Actions 构建镜像，服务器按现有方式拉取；不再单独发布客服 Python 服务 |

不通过 Memos PAT 请求自身 HTTP 接口；内部调用仍需保留身份、权限、空间和业务校验，不直接绕过业务层写笔记表。微信凭据继续受保护，并不会因为内置化而消失。凭据保存机制、具体路由和包名在实现时按现有代码模式确定，不能把未实现的配置写成可用说明。

## 第一阶段实现（2026-09-19）

- `internal/wechatkf`：回调加解密与有界 XML 校验，官方 API 客户端（拉取、媒体、回执、账号与客户信息），消息转换、白名单和单次剪藏处理。
- `server/router/api/v1/wechat_kf_notes.go`：从可信配置绑定 Memos 用户与空间，复用现有笔记/附件服务；逐次校验用户、空间、资源归属和私有性。默认空间为空，标签独立保存。
- 沿用 Python 的固定笔记/附件/回执 ID。单次处理返回结果；队列必须先持久化结果、预留窗口额度，再调用发送接口。网络结果不确定不在客户端盲目重试。
- 合成消息和临时 SQLite 集成测试覆盖实际业务保存、媒体失败后恢复、重复处理和权限边界；没有调用生产服务。

此阶段不注册公开回调、不启动消费者，不提供可用配置开关。持久化队列、事件处理、回执窗口与调度、管理界面、旧状态导入和正式切换仍需后续实现。不能直接把客户端和处理器接到回调后返回成功，否则会失去持久化保障。

## 必须保留的行为

- 本人白名单；未绑定或空白名单拒绝剪藏。默认 PRIVATE、个人空间。
- 正文只保留实际内容；顶层 #tag 独立保存，历史聊天井号不变；默认微信剪藏与聊天记录标签，均可配置。
- 文字、图片、语音、视频、文件、位置、小程序、视频号、商品/订单、聊天记录与链接兼容解析；媒体创建笔记并关联附件。按旧实现范围保留可获取数据及未知/部分内容的诚实提示。
- 独立微信笔记不建占位；聊天记录内缺失内容报告部分保存。不开启 OCR、转写、全文抓取等新范围。
- 会话进入、撤回及发送失败事件按旧规则处理，支持必要账号/客户信息读取；不因撤回自动删除已存笔记。
- 只发最终“类型保存成功”；失败给脱敏具体原因，不发“收到”、链接或通用重发提示。保留窗口额度、固定消息 ID、发送失败关联和发送结果不确定时不盲目重试。
- 游标与入队事务、固定笔记/附件 ID、重试、重启恢复、成功与最终回执的持久化关联。媒体只由 Memos 长期存储。

旧服务曾通过 51 项测试，迁移以这些行为和实际规则为依据；不要求 Go 测试数量恰好相同，也不能沿用旧测试结果声称新实现已通过。

## 迁移与切换

1. 在本机可丢弃数据中完成协议、消息、业务保存、配置界面和后台队列，验证禁用状态不影响普通 Memos。
2. 增加可重复执行的导入工具，将旧服务游标、去重标识、待处理任务、已关联笔记、回执窗口和回执投递结果迁入 Memos；固定 ID 兼容已存在笔记。已发送和不确定的回执不得重新排成普通待发送任务。
3. 通过三驱动结构检查、功能测试和容器新装/升级验证；密钥、真实聊天及旧状态库不进入 Git 或 CI 测试材料。
4. 切换时按私有运维记录备份旧配置/完整状态目录和 Memos 数据附件；停止旧消费者后导入最后状态，再将回调交给内置模块。保留回退方案，避免两个消费者同时运行。
5. 用本人真实文字、聊天记录、媒体及回执验证保存结果与无重复；成功后再处理旧服务停用、过期 PAT 撤销及遗留部署文件。独立仓库是否归档另行决定，不在本次文档调整中操作。

新功能跟随既有版本 PR 发布。普通文档 PR 不部署，也不能把方案接受或 PR 合并当成迁移完成。
