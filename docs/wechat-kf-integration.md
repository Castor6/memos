# 内置微信客服

微信客服剪藏作为 Go 模块运行在 Memos 内，随同一应用、镜像和版本发布。管理入口为「设置 → 微信客服」，仅管理员可见，默认关闭。实施与验证事实见[主任务](tasks/TASK-20260919-wechat-kf-integration.md)。

## 保存行为

本人主动发送或转发内容到客服会话，一条消息保存为一篇 PRIVATE 笔记，默认进入绑定用户的个人空间。正文只保留实际内容，不添加剪藏标题、来源、转发时间或接口辅助字段。顶层文字的 `#tag` 转为独立标签；聊天记录内原有井号保留。默认标签为「微信剪藏」，聊天记录另加「微信聊天记录」，均可配置。

| 微信消息 | 保存内容 |
| --- | --- |
| 文字 | 正文与独立标签；纯文本网址仍按文字处理 |
| 图片、语音、视频、文件 | 一篇笔记及关联附件；不做 OCR 或语音转写 |
| 链接卡片 | 官方提供的标题、描述、链接等；不额外抓取文章全文 |
| 位置、小程序、视频号、商品、订单 | 官方可获取字段及链接，不推断缺失内容 |
| 聊天记录 | 保留标题、发送者、时间、顺序及可获取内容和附件 |
| 独立微信笔记 | 不建占位笔记，回复接口未提供内容 |

聊天记录中的不支持/缺失内容保留说明并报告部分保存。未知类型保留有用原始字段及类型提示。会话进入、撤回、发送失败等授权事件去重保存 30 天；撤回不自动删除已有笔记。

只对本人白名单处理和回复，不能自动授权第一个访客。成功只发「类型保存成功」，不发「收到」、笔记链接或其他附加信息。保存失败最多自动尝试 12 次，最终回复失败环节、脱敏原因及尝试次数；已有笔记时说明部分保存。

## 配置与账号

沿用[官方独立客服后台](https://kf.weixin.qq.com/)的企业 ID、客服 Secret、`open_kfid`、Token 和 EncodingAESKey；这不是公众号或企业微信自建应用。未认证账号也有平台分配的企业 ID。个人账号开通的成功路径、当时额度及公网 IP HTTPS 实测边界保留在[开通历史](wechat-kf/legacy/onboarding.md)；其中 Python、PAT 和 systemd 步骤只作历史参照。

1. 管理员在设置页填写绑定用户、企业 ID、客服账号、本人 `external_userid` 白名单和回调密钥。已有用户迁移使用下述导入工具，避免手动复制。
2. 保存设置，使用「测试已保存的配置」核对官方客服账号访问权限。测试不发送消息，也不代表素材和回执端到端已验收。
3. 反向代理精确路径 `/wechat/callback` 到 Memos 服务，官方后台填写同一 HTTPS URL、Token、EncodingAESKey。配置完整但关闭时支持 GET 验证；POST 返回 503，不假装已接收消息。
4. 开启模块，发送自己的测试消息，在 Memos 检查笔记和标签，并在微信确认最终回执。设置页可查看消费者、队列、同步错误及最近处理结果。

密钥以现有 Memos 实例密钥派生的 AES-GCM 加密后入库；管理接口仅返回「已配置」，密码框留空表示保留原值。备份必须包含 Memos 数据库及其中的实例密钥。权限不变：普通用户不能读取/修改接入设置或状态。本人白名单、默认标签、附件大小和回执开关可调整；已有处理记录后禁止直接更换企业、客服账号、保存用户或空间，避免重放进另一绑定。

内置保存直接复用笔记、标签、附件和权限服务，不需要 Memos PAT，也不请求自己的 HTTP API。新安装的发送者身份必须由管理员通过官方消息数据人工核对；现有迁移会保留原本人白名单，不开放匿名自动绑定。

## 持久化与故障行为

- `internal/wechatkf` 处理官方 API、签名/AES、消息转换；`server/runner/wechatkf` 接收回调并运行后台消费者；业务写入位于 `server/router/api/v1/wechat_kf_notes.go`。
- `store/wechat_kf*.go` 管理三驱动专用表，游标与入队同事务。后台使用数据库租约避免多个 Memos 进程同时消费；重启或配置变更先停止旧任务再接管。
- 固定来源 ID 与旧服务一致。笔记草稿进度先落库，再处理附件；成功结果与最终回执同事务保存。完成后清空原始消息，失败任务保留必要恢复信息。
- 附件只由 Memos 长期保存，微信下载使用有界内存；不再运行独立 SQLite。旧 SQLite 仅是离线导入源和私有备份。
- 按[官方发送接口](https://kf.weixin.qq.com/api/doc/path/94744)维护最近主动输入后的 48 小时/5 次窗口，新输入重置，重复拉取不重置。每次发送前持久化预留额度；窗口耗尽可能等待新输入或过期。
- 网络结果不确定或发送中进程中断记为 `unknown`，不盲目重发；明确 API 拒绝在限额内退避，异步 `msg_send_fail` 关联为 `delivery_failed`。`sent` 仅表示接口接受，不代表手机已读。回执失败不回滚笔记。
- 微信网络调用有超时、大小、主机和重定向限制。错误不包含带令牌 URL、远端正文、密钥或原始聊天；排障查看阶段、错误码、队列和私有日志。

## 从 Python 服务迁移

先备份 Memos 数据、附件和配置，以及旧服务的完整状态/私有配置。新版本默认关闭，可先升级 Memos，仍由旧服务处理消息。准备切换时停止旧消费者，再生成一致的旧 SQLite 快照，不能让两个服务同时消费。

```sh
memos import-wechat-kf \
  --data /path/to/memos-data \
  --state /private/backup/state.db \
  --env /private/backup/service.env \
  --owner your-memos-username
```

命令复用 `--driver`/`--dsn`，目标可为 SQLite、MySQL、PostgreSQL；源必须为旧服务 SQLite。只输出导入计数，不输出内容或配置。文件只读，导入事务化；重复执行按 ID 跳过已有记录，不回退游标或覆盖新进度。必须有已初始化的 Memos 实例和正常绑定用户，目标模块关闭且无活动消费者。导入保留已完成任务、游标、待处理任务、固定笔记 ID、回执窗口及发送状态；`sending` 转为 `unknown`，已发送结果不会重发。Memos PAT 不读取、不迁入。

核对导入计数和 ID 对应关系后，保存/测试内置配置，将原 Nginx 精确回调路径改为 Memos 上游并开启模块。官方 URL、Token、AES Key、企业和客服账号保持一致时，微信后台无需改设置。核对原笔记和附件不变，再验证新文字、聊天记录、媒体及回执；确认后禁用旧 systemd 服务。

切换失败先关闭新消费者并停止其写入，再恢复原代理和旧服务。若新服务已处理新消息，必须先核对/回迁新队列、游标和发送结果；不能直接拿旧快照启动并假定无重复。数据库降级使用升级前备份，不把旧二进制直接连向已升级结构。实际服务器路径、备份位置和切换证据只写私有运维记录。
