# 个人 Fork：协作与开发入口

以官方 `v0.30.0` 为源码基线，在 `main` 维护个人定制，按需吸收 `upstream` 的修复或功能。

## 按需导航

| 现在要做什么 | 去哪里 |
| --- | --- |
| 查找某个需求、问题或历史结论 | 搜索 [任务索引](tasks/INDEX.md)，只打开相关详情 |
| 记录新的实质需求或修复 | 使用 [任务模板](tasks/TEMPLATE.md)，同步更新索引 |
| 启动本地应用、准备数据或验证修改 | [本地开发与验证](development.md) |
| 提交发布说明、了解 CI 和版本 PR | [CI 与版本流程](release.md) |
| 了解上游基线、个人差异、发布和部署方案 | [定制与部署记录](customization-and-deployment.zh-CN.md) |
| 查看长期协作和代码规则 | [AGENTS.md](../AGENTS.md) |

## 记录维护方式

- 助手负责把讨论中的需求、验收标准和关键取舍整理成记录，完成后补充实际结果。
- 任务详情按需检索，不要求每次启动读取全部历史。知道任务编号时直接打开对应文件。
- 索引每项只保留一行：编号、标题、状态、模块/关键词和详情路径。状态以详情中的最新结论为准。
- 任务使用 `TASK-YYYYMMDD-短主题` 编号，文件名保持稳定。已完成不等于已上线；详情单独记录部署状态。
- 索引过长时，按年份归档到 `tasks/archive/YYYY/INDEX.md`，主索引只保留活动任务及归档入口；归档同样可检索。
- 重要的长期要求应提炼到协作规则或模块文档，并链接原任务，避免埋在历史记录中。
- 原始聊天、整段日志、测试数据库、账号会话和截图默认留在被 Git 忽略的本地目录；任务文档记录精简结果和复现步骤。
- 源码和通用方案随 Git 维护。真实部署地址、凭据、笔记、备份及运维详情继续放在独立的私有维护目录。
