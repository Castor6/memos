## 背景与目标

为 Star 与 Pick up 默认添加小写同名标签，并像 Memos 编辑器一样选择或新建独立标签。完整保存预览渲染 Markdown，统一 Pick up 模板名称。用户追加修复 Memos 正文链接下划线在字母下伸部位断开的问题。

## 验收标准

- [x] 新草稿默认带 `star` 或 `pick up` 标签；支持搜索已有标签、新建、移除，保存为 Memos 独立标签。
- [x] 标签随草稿恢复及重新提取保留，按模式和账号隔离；保存重试包含标签一致性检查。
- [x] 完整预览渲染 Markdown 和长文折叠，验证不可信 HTML 的安全处理。
- [x] 模板与编辑界面使用 `Pick up`、`Context & thinking`、`What they put down`。
- [x] Memos 正文链接的下划线连续显示，检查中英文、标题和多行 URL。
- [x] 完成扩展 lint、测试、构建、打包检查与本地界面验证，记录未覆盖范围。

## 讨论结论

- “补充背景”命名为 `Context & thinking`，表示形成评论之前的背景、线索与思考过程，与已发表的 Pick up 原话区分。
- 使用既有 Memos `tags` / `explicitTags` 接口和当前个人空间，不修改服务端 schema、认证或发布流程。
- 默认标签可按普通标签移除，重新提取不会重新添加用户已移除的默认标签。
- 旧草稿保存结果未知时保留原提交正文和原标签语义，先完成原请求核对。

## 实现结果

- 标签控件支持筛选、新建、移除、键盘选择及中文输入法，按服务端规则限制 100 个标签、每个 256 UTF-8 字节。候选合并当前用户的使用统计和标签配置；读取失败可重试，同时保留新建能力。
- 弹窗经后台发送 `tags` 和 `explicitTags: true`，不将原文话题意外归入独立标签。标签纳入保存指纹；已确认成功且快照一致的记录允许用户后来在 Memos 中修改标签，未知结果仍严格核对。
- 草稿保存标签与原请求正文，旧草稿未确认的保存继续使用旧模板和旧标签语义，避免升级后重试产生不一致。重新提取保留用户标签，含主动清空的标签列表。
- 预览和历史正文复用安全 Markdown 组件，基于主站同类渲染依赖处理 GFM 与 HTML 折叠；保留软换行，清理脚本、事件和危险链接。Pick up 编辑区、模板及历史展示采用用户确认的名称，不批量改写已保存正文。
- Memos 共用正文链接样式及扩展预览设置 `text-decoration-skip-ink: none`，保留换行和原链接行为。
- 新增中文 patch Changeset，扩展 README 与局部维护约定同步更新。
