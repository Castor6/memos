## 背景与用户已表达的要求

- 浏览器扩展 Star 保存的原链接应放在“展开原内容”上方；历史笔记可以略过处理。
- 增加逐条控制的私密能力，目标是不让 AI 搜索、读取或修改这些笔记，同时本人在软件内正常搜索和查看。
- 置顶展示应比当前右上角小图标更明显。
- 首轮先检查代码并对齐需求；2026-10-17 用户选择第一种置顶样式“徽标与侧线”，并明确授权开始实现。
- 用户补充：MCP 使用配置的 API 令牌，提出这项功能的本意是不让 AI 读取；对 MCP 与直接 API 调用的区别需要解释，而非让用户先选择技术方案。
- 用户明确选择分享权限独立，不因开启该功能自动修改公开可见性或关闭已有分享链接。
- 用户随后明确：AI 获取本人 Memos 数据均通过 MCP，因此本期只限制 MCP 入口，普通 API 不纳入保护范围，不扩展 PAT 权限设计。
- 用户结合截图进一步明确：把“展开原内容”内最底部现有的收藏网页链接移动到折叠区上方，仍在原有“原内容”标题下，不新增类别或新的一级分区；要求先查看置顶样式效果。

## 代码调查结论

- 普通网页 Star 将默认或自定义模板结果作为原文；默认模板的来源链接在正文尾部。X Star 也在原文尾部追加来源链接。`composeCaptureMemo` 对超过 1600 字符的整段原文添加折叠，因此链接随原文一起隐藏。
- 扩展预览与新保存共用内容组装函数；历史笔记不会重新套模板。旧的结果未知保存请求需要保留冻结正文，不能改变幂等重试的内容。
- 现有 `PRIVATE` 表示仅创建者可见，不能屏蔽以创建者身份访问的 MCP。MCP 将原始 Authorization 转发至普通 API，同一 PAT 也可直接访问普通 API。
- MCP 工具包含笔记、评论、附件、表情及关联操作。仅过滤 ListMemos 不足以阻止已知 ID 读取、删除、附件操作或关联摘要泄露。
- 结构化笔记引用会将目标摘要写入正文，因此屏蔽关联响应仍不足。普通笔记内指向受保护笔记的引用、附件链接及其派生摘要需要一致处理；MCP 修改经过隐藏处理的正文时也不能覆盖原引用。
- 当前置顶图标位于卡片头部右侧，点击直接取消置顶；首页等入口已有置顶优先排序，视觉调整无需改变排序规则。

## 已确认方案与实现

- Star 保留“我的思考（可选）／原内容”的原有分区：将扩展自动生成的来源链接移至“原内容”标题下、折叠正文上方。覆盖新 WEB 默认模板与 X Star；短原文同样先显示链接，自定义模板和用户主动编写的链接保留。Pick up、旧草稿、历史笔记和结果未知的冻结请求不改写。
- 编辑器与笔记菜单提供“私密”开关，说明为“对 MCP 隐藏，软件内使用和分享权限不受影响”；卡片显示私密标识。历史笔记默认关闭，待办与评论共用该字段。独立于现有 `PRIVATE` 可见性，不改令牌权限及认证方式。
- MCP adapter 在进程内标记请求上下文，无法用客户端请求头伪造；服务层拒绝受保护笔记的已知 ID 读取、更新、删除，MCP 也不能设置或关闭保护。搜索在分页前排除受保护条目；三驱动递归查询覆盖多层评论、附件及双向关联。
- 可识别的私密笔记/附件引用连同其缓存摘要按 Markdown 段落删减；Capture 快照、跨空间引用和多跳引用同样检查，派生摘要重建。递归限制为 64 层、256 次访问，超限保守隐藏。含删减引用的笔记不能通过 MCP 整体替换正文、附件或关联；MCP 带过滤条件的列表会排除这类笔记，避免从过滤是否命中推断隐藏摘要。
- 删除普通笔记若会间接删除私密评论或私密笔记的关联，则要求回到软件内操作。普通 API、本人软件内搜索/查看/编辑及独立分享授权保持原规则。
- 新增 `mcp_hidden` 字段与 SQLite/MySQL/PostgreSQL 迁移（schema 0.30.7），同步生成 API 输出，备份导出/导入保留私密状态。
- 置顶采用头部“已置顶”徽标和 3px 左侧强调线；取消置顶保留在菜单，排序不变。侧线独立于主题边框，避免 flomo 透明边框覆盖。
- 编辑器仅在用户改变私密开关时提交该字段，避免旧编辑器保存正文时覆盖另一个标签页的新隐私设置。

## 选择原因与限制

- 用户确认实际 AI 访问只走 MCP，取代此前同时限制普通 API/PAT 的建议；本次不重做令牌权限。
- 分享权限由用户明确选择保持独立，公开或分享出去的内容仍按现有规则访问；该开关不能撤回已读信息，也不追溯普通文本的手工复制。
- Star 旧请求需要保持幂等重试正文，故通过新草稿字段选择新布局，不批量改写已有内容。
- 置顶方案由独立预览的三种样式中选定；真实组件沿用现有主题配色和布局。
