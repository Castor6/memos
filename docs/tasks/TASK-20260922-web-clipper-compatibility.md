- 官方仓库 main 基线为 `90ee20fa4ae226f68c6eb1c282f48c6309fb7bce`；GitHub 最新发布为 [v0.4.1](https://github.com/usememos/web-clipper/releases/tag/v0.4.1)。该发布标签的 `src/lib/versions.ts` 与检查到的 main 版本门槛相同：仅接受不低于 0.26.0 的 0.x 正式版及符合规则的 RC。
- 下载官方 `versions.ts`，使用 Node 22.23.1 的类型剥离功能和 npm 自带 semver 执行原始校验函数。结果：0.7.0、dev、0.25.0 返回 false；0.26.0、0.30.0 返回 true。临时源码和脚本保存在忽略的 `tmp/web-clipper-audit/`。
- 本仓库 `package.json` 为 0.7.0；`.github/workflows/release-candidate.yml` 将该版本编入 `internal/version.Version`；`cmd/memos/main.go` 将其传入实例 Profile；`server/router/api/v1/instance_service.go` 原样返回。因此按当前流程构建的发布版本会被扩展拒绝。
- 静态对照 `src/lib/memos-client.ts`：扩展使用 Bearer PAT；`GET /api/v1/auth/me` 所需的 user.name、创建笔记与附件的 REST 路由及 JSON body 形状均有对应支持，笔记详情链接 `/memos/{uid}` 也匹配。本结论不等于实际请求全部成功。
- 扩展不发送 `X-Memos-Space`，本仓库将其处理为默认个人空间；不能在扩展中选择自定义空间。
- 扩展没有发送独立 tags/explicitTags；本仓库 `RebuildMemoPayload` 在 explicitTags 为 false 时保留正文标签提取兼容，因此正文中的有效标签仍可提取，原文字不自动删除。扩展不提供定制版独立标签选择能力。
- 图片上传的 filename/type/base64 content 和笔记 attachments 名称列表，与本仓库 proto 及服务端处理静态匹配。
