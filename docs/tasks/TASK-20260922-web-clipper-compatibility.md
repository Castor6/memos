### 轻量 OCR 样图实测（2026-09-22）

实际方法与结果：

- 独立 venv 使用 Python 3.12.10、RapidOCR 3.4.5、ONNX Runtime 1.30.0、OpenCV 5.0.0.93；测试机为 Windows 11、Core Ultra 7 265KF、约 64GB RAM。显式加载 PP-OCRv4 mobile 检测与识别 ONNX 文件，实际大小为 4,745,517 与 10,857,958 字节。
- 所有 ONNX 会话验证为 CPU provider、intra/inter-op 均 1 线程；OpenCV 为 1 线程，识别 batch=1，关闭 CPU memory arena。方向分类推理关闭，但 RapidOCR 3.4.5 仍初始化其小模型，实测内存包含该部分。
- 用户原图为 1200×3798；两组全局长边上限均为 2000。基线检测器使用 `min/736`，对照为 `max/1280`，分别在新进程识别同一图片 3 次。原图未修改；推理阶段禁止 Python socket 联网，未上传图片。
- 两组都识别出整图 35 个文字块，本人评论人工核对范围内 27 行无漏行；Unicode NFKC 归一化并去除空白后，383 个基准字符中均有 1 处替换：把“输入”识为“输人”，样本字符错误率约 0.261%。该数字不统计英文空格粘连，不能当作通用模型准确率。
- 中英文主要内容、大小写、人名与术语核对一致；英文词间有空格丢失、括号全半角混用。点赞图标被识成“凸”；作者渐隐回复仅提取可见文字。本人/他人区分使用人工确认的图片区域做评估，本轮未实现自动卡片分区，不会把整图文字直接当作本人评论。
- 基线首次识别 3.84 秒，后两次 2.19/2.11 秒，连续三次进程峰值工作集 431.35 MiB；1280 配置首次识别 3.75 秒，后两次 1.64/1.64 秒，总峰值工作集 359.28 MiB，第一次识别时峰值 301.28 MiB。
- 1280 配置从脚本启动到首次结果 4.35 秒（含导入、模型初始化和识别，不含下载安装）；处理后当前工作集约 115.53 MiB。内存指标为 Windows 进程峰值工作集，包含运行库和中间计算；并非 Linux RSS、生产服务器测量或模型文件体积。不同进程的文件缓存状态未控制。
- 结论：对这一张清晰分享原图，轻量 OCR 能提供完整、可校对的本人评论，1280 配置在未增加实质错字的情况下减少耗时与内存。可继续评估服务器单任务异步集成，但尚不能承诺小规格服务器共存容量或识别速度。
- 本地原始输出、人工基准、逐行坐标/置信度、模型哈希、冻结依赖、复现脚本和报告保存在忽略目录 `tmp/ocr-validation-20260922/`，不加入版本控制。产品代码、依赖清单、Docker 与线上配置均未变更；任务文档通过工作区与暂存区空白检查。

未覆盖：微信客服实际下载/压缩版本、其他卡片版式、模糊或旋转图片、多样本准确率、并发/长期常驻、Linux/Alpine 和多架构、真实服务器内存余量及 Memos 同时响应。依赖下载及本机单图成功不等于部署或生产验收。
