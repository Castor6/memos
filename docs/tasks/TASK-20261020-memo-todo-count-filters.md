## 实施方案

2026-10-20 用户选定“并集／交集”普通下拉框并明确授权实施。沿用此前方案，具体规则如下：

- 字数位置细节：卡片时间旁显示“128 字”，详情基础信息中显示字数，编辑器底部实时显示；三处使用相同口径。
- 字数口径：中文按字、英文按词、连续数字按一个单位；不计空白、标点、Markdown 格式标记、独立标签、附件及引用卡片的自动摘要；折叠正文计入全文，链接只统计显示文字。三处共用同一统计函数。
- 多选交互：再次点击已选标签可取消；展示全部已选标签，支持逐项移除与清空。用户已选定第二张静态图中的带边框小型下拉，默认“并集”，另一个选项为“交集”，选中状态通过背景与文字高亮表示，不显示对勾。
- 筛选状态：标签选择和组合方式随 URL 保留，刷新及浏览器后退保持；清空标签后恢复默认“任意一个”。
- 新建内容的标签继承：建议继承全部已选标签；取消筛选时仍只撤回自动带入的标签，保留手动标签。此项是多选后对现有行为的延续建议。
- “有未完成待办”：正文至少有一个未勾选的实际任务项时匹配；全完成、无任务项、代码块中的示例复选框不匹配。筛选返回整条笔记或待办，正文中已完成项仍保留。
- “私密”：按当前界面“对 MCP 隐藏”的开关理解，不等同于分享可见性中的“私有”。沿用现有产品定义。
- 筛选入口：用户明确要求采用可点选标签，不使用开关样式；点击筛选、再次点击取消。当前文案建议为“未完成”“私密”，默认均未选中，可分别选择或组合。
- 不同筛选维度建议取交集：例如同时满足所选标签、有未完成待办、私密，且可继续叠加现有搜索和日期条件；笔记、待办及空间边界沿用现有规则。

上述为当前实施范围；以下按日期保留前序需求对齐和预览事实。

- [侧栏标签](../../web/src/components/MemoExplorer/TagsSection.tsx)、[标签树](../../web/src/components/TagTree.tsx)、[正文标签](../../web/src/components/MemoContent/Tag.tsx)选中新标签时清空旧标签，因此界面当前为单选。
- [筛选状态](../../web/src/contexts/MemoFilterContext.tsx)可保存多个标签条件并同步 URL；[筛选生成](../../web/src/hooks/useMemoFilters.ts)按 AND 拼接多个标签条件，后端也支持任一标签匹配。
- [后端筛选定义](../../internal/filter/schema.go)已有 `has_incomplete_tasks`；[Markdown 属性提取](../../internal/markdown/markdown.go)按实际任务节点判断未完成状态，与是否为独立待办类型无关。
- [私密历史决定](TASK-20261017-clipper-privacy-pin.md)明确界面“私密”对应 `mcp_hidden`，分享可见性独立；新增筛选需沿用该语义。
- `mcp_hidden` 已有三驱动存储与 API 读写；共用 CEL 筛选尚未声明该字段，需要增加布尔列筛选支持，不能把现有 MCP 排除逻辑当作“只看私密”的筛选。
- 侧栏标签统计当前按入口、作者等范围计算，不随普通筛选变化；本轮没有确认动态标签计数需求。
