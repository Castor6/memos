# GHCR 主渠道与 ACR 备用渠道

- 记录日期：2026-09-26
- 模块与关键词：发布、镜像仓库、自动更新、手动选择渠道
- 维护归属：feat/ghcr-primary-acr-fallback

## 背景与目标

用户授权采用 GHCR 主用、ACR 备用，避免单一仓库不可用阻断发布和部署。

## 验收标准

- [ ] 已测试版本优先发布 GHCR，只向所选渠道发布，默认不联系 ACR。
- [ ] 手动转仓时保持摘要，切换后继续验证来源、平台和版本，禁止降级或同版本替换。
- [ ] 跨仓库同摘要不重启；失败摘要不能换仓库绕过；保留备份和恢复规则。
- [ ] 验证单元测试、工作流与服务器安装，记录实际边界。

## 讨论结论

普通 PR 不触发应用发布。提供受主分支限制的手动镜像同步工作流，迁移最新已发布版本。镜像以摘要复制，不重新构建现有版本。用户明确要求不双发、不自动切换；新版本保留升级测试，已验证版本转仓只校验一致性。旧仓库列入保留范围仅用于验证运行镜像和备份清理，不作为网络故障自动回退源。

## 实现与验证事实（2026-09-26）

统一使用 `IMAGE_CHANNEL` 显式选择发布渠道，默认 GHCR，即使保留 ACR 凭据也不双发。手动转仓工作流与发布共用并发锁，以正式 Release 的 SHA256SUMS、元数据及镜像摘要确认来源，保持 digest 复制当前版，拒绝覆盖冲突版本和倒退 stable。转仓后按部署说明协调仓库变量和服务器更新器配置；不向 GitHub 添加 SSH 私钥。

更新器仅访问所选仓库；跨仓库相同 digest 不重启，失败 digest 不能换仓库绕过，旧仓库仍可用于识别历史恢复镜像。本次只修改宿主机和发布工具，不改应用或扩展版本，不创建应用版本 Changeset。

本机 Python 发布、转仓及更新器测试通过；macOS 跳过依赖 GNU tar 的恢复测试，Linux CI 继续执行这些测试。工作流 Actionlint 通过。实际服务器切换与转仓结果保存在私有运维记录，不能由源码修改推定已完成。
