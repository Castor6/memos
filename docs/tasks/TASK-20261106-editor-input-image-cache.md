### 保存后的首尾空行展示

- 只在阅读展示时忽略整篇正文首尾的空行；编辑器内容和保存原文保持原样。
- 保留编辑器首尾空行作为输入位置，尤其允许在折叠区末尾继续输入其他内容。
- 正文中间、折叠内部、列表及代码内部的空白保持原样；不改变修改判断与更新时间规则。
- 根级空白段落的渲染处理是现有调查建议，具体实现应保证上述语义，不以裁剪保存原文代替。

### End 键定位

- Windows 和 macOS 编辑内容时，单独按 End 将光标移到屏幕上当前显示行的末尾，不触发页面滚到底部。
- 长段落自动折行时定位到当前视觉行末，不直接跳到整段末尾；验收覆盖普通文本、折叠标题/正文和代码。
- Shift-End、Ctrl-End、Cmd-End 等组合键不在本次新增行为范围内。

### 上传图片缓存

- 目标场景为手机和电脑的普通浏览器再次访问，以及 PWA 重新打开；已经看过且未改变的自上传图片应复用可用缓存，避免每次整图下载并逐段显示。
- 用户接受先采用 30 天浏览器私有缓存：`Cache-Control: private, max-age=2592000, must-revalidate`。一小时方案由此替代；当前线上 `no-store` 覆盖规则需要在实施时调整。
- 30 天是缓存可直接复用的新鲜期，不是强制删除或重新下载的期限。新鲜期内普通访问可直接使用缓存；到期后向服务器验证，图片未变且条件请求受支持时返回 `304`，继续复用原图片正文。
- `private` 限制共享缓存，不表示按登录账号隔离。采用长缓存后，退出登录、删除图片或撤销权限不会自动清除浏览器中仍处于新鲜期的图片；后续实际到达服务端的请求仍须执行现有权限校验。
- 浏览器可因空间不足或用户清理而提前移除缓存，不承诺图片一定保留满 30 天；清理后再次下载属于正常行为。
- 新鲜期内若同一 URL 的图片内容被替换，浏览器可能继续显示旧图。实现需保留“更新图片使用新地址”的约束，不能承诺覆盖原地址后立即更新所有缓存。
- 本次不采用一年缓存或 `immutable`：当前尚未保证附件地址永不被其他内容复用。图片地址版本化、缩略图优化及 Service Worker 离线缓存保留为独立评估项，不纳入本次已确认方案。
- 当前条件请求能力已确认针对本地原图，不能直接推定数据库原图、S3 代理、S3 直链或缩略图同样支持 `304`。实施时需核对实际存储路径，并验证成功响应、条件请求和错误响应的缓存头，避免扩大缓存到错误或未授权响应。

首尾空行最小探针：使用现有 Node、jsdom、Tiptap 与 ReactMarkdown 验证，单个首尾空段落序列化为普通换行，阅读时不显示；连续空段落的第二个起被 Tiptap 序列化为 `&nbsp;`，阅读时会产生有高度的空白段落。两个首空段落、正文、两个尾空段落生成 `\n\n&nbsp;\n\nBody\n\n\n\n&nbsp;`，阅读输出为正文前后各一个 NBSP 段落。因此建议只清理阅读渲染树根级首尾的空白段落，不使用字符串 `trim()`，不递归清理折叠、列表或代码内部。探针未修改产品代码或依赖，尚未进行浏览器布局验收。
