## 背景与目标

从项目审查进入用户授权的实施，修复可能影响内容和附件一致性的边界，并减少链接后台和前端列表的重复工作。审查起点为 `7d609777`，交付基于 `origin/main`，不夹带该起点尚未合并的剪藏扩展提交。

用户明确将两个剪藏事项（扩展业务错误提示、扩展 CI）交给另一个会话。本次也不调整 Docker/发布工作流或 Proto 生成器版本。

## 验收标准

- [x] 保存期间完整只读，成功后清空已提交编辑；失败保留草稿，保存反馈不等待全列表刷新。
- [x] 全请求验证及数据库失败不提前删除附件文件，附件关系与笔记一起提交，物理清理持久重试。

- [x] 链接成功快照永久复用；待处理任务、失败退避和历史补抓可恢复，前后台协调同一 URL。

## 讨论结论

用户通常不会在点击保存后继续编辑，因此采用保存期间完整只读的简单保护，不引入编辑版本合并。冻结覆盖正文、工具栏、拖放/粘贴入口以及已打开菜单的迟到回调。

附件原风险需区分正常界面与 API 边界：普通编辑器不发送 `space`，`[attachments,space]` 只是构造的失败请求示例；正常流程也可能在物理删除后遇到数据库失败。本次用故障注入验证修复，不将静态发现描述为线上事故。

Webhook 是用户配置接收地址后向外发送笔记事件的集成，与微信客服入站回调不同。修复其 DNS 校验与实际连接之间的缺口，不改认证方式。

对齐原链接任务：成功缓存本来已能避免通常的重复外网抓取，本次减少的是全库扫描、未成功 URL 的过密重试及首次并发抓取。无 TTL，不自动刷新成功标题或摘要。长期规则见 [链接预览说明](../link-previews.md)。

## 实现结果

2026-09-22：

- 编辑器保存期间只读且 reducer 拒绝编辑操作；保存后不等待列表网络请求。浏览器复审发现 Tiptap 切换只读默认触发更新、导致 RESET 后旧正文恢复，已改为不发更新事件，并补真实编辑器回归。
- 列表、统计及详情刷新按查询键合并，重叠键串行并保留必要的尾随刷新，无关键可并行；React Query 的取消信号传递给 Connect 请求。SSE 表情事件只刷新包含目标笔记的列表，不刷新全局统计。
- 笔记更新先完成字段、附件和引用验证，再以事务提交正文、关系及待清理记录。单笔记附件元数据查询不再被默认 100 条截断。事务按 ID 锁定当前和请求附件的联合集合，覆盖删除与并发转绑。
- `attachment_cleanup` 保存清理快照，启动及每分钟处理最多 100 个任务，失败退避、重启恢复，S3 配置随任务保留。三驱动增加 `04__attachment_cleanup.sql` 并同步新建表结构。
- 新上传的本地文件与 S3 对象独立生成随机存储后缀，保留模板目录和界面文件名，避免附件 UID/同名路径复用后被旧任务误删。历史共享存储对象仍有引用时跳过物理删除；S3 按待清理 key 筛选，历史本地相对/绝对/软链接别名须在有清理任务时每批读取一次 LOCAL 引用元数据，不读取文件内容。
- `link_metadata_job` 持久保存 URL 任务及租约，`link_metadata_backfill` 保存历史补抓上界/游标；写笔记与登记 URL 同事务。每轮回填 100 条、最多抓取 8 个 URL，失败 1 分钟至 24 小时退避；成功快照永不覆盖。三驱动增加 `05__link_metadata_queue.sql`。无效 URL 入队前拒绝，API 保持 `InvalidArgument`，笔记中的无效链接不阻止正文保存。
- 临时预览接口独有的失败任务保留 15 分钟，按索引每批最多回收 100 个，不自动成为永久后台重试；笔记登记原子提升同 URL 任务并保留租约/退避，接口不能反向降级。不改变公开预览接口的认证规则或成功快照寿命。
- Webhook 一次解析、校验全部结果后，直接连接选定 IP；保留原 HTTP Host/TLS 主机名，支持多地址回退。
- 首次/分页/后台列表错误显示重试，保留已有内容。附件媒体、音频、文档各自在服务端筛选分页；PSD/MIDI 保持文档分类，动态照片图片与视频留在同一媒体查询；未使用附件独立查询。
