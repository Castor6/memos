## 背景与目标

用户确认不压缩备份，授权按最近 3 次加最近 30 天的规则清理，并保留对应镜像。

## 验收标准

- [x] 未压缩 tar 保持不变；最近 3 次或最近 30 天任一条件满足即保留。
- [x] 当前恢复点、失败/未完成升级、异常或缺失元数据的备份受保护。
- [x] 只删除被清理备份关联、未被其余备份或任何容器引用的 Memos 镜像，不使用全局 prune。
- [x] 成功升级后才自动清理，失败不影响已成功上线的服务；提供持锁只读预览与清理日志。
- [x] 测试边界、删除失败、失败升级、共享镜像、当前镜像、未知文件及符号链接；服务器隔离测试和生产预览通过。
- [ ] 服务器更新器安装前备份，现有两份备份验证后补充元数据，维护记录同步。

## 实现与验证

2026-09-17：本地 Python 28 项测试通过（macOS 跳过两项 GNU tar 用例），Linux 临时目录全部 28 项通过；根目录 7 项版本/CI 规则测试通过。真实隔离 Compose + HTTPS 演练验证成功升级后执行清理、候选镜像故意损坏附件后按旧镜像完整 ID 恢复、SQLite/附件哈希保留及登录。演练不操作生产数据，不重载生产 Nginx。

清理只关联归档元数据中的旧镜像；未知/残缺目录阻止清理，异常归档与失败升级保留。清理错误不进入应用回滚事务。补充旧镜像失去仓库摘要引用时的恢复处理，恢复的 overlay 使用已验证本地 ID。实际旧备份元数据迁移、宿主机安装与生产预览由本次维护任务继续执行，私有细节仅写本机运维目录。
