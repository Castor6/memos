## 2026-10-22：退出重开直接显示完整界面

用户在 0.11.3 上录屏反馈：退出后重新打开，约一秒内先出现灰色框架、导航、侧栏和列表占位，再逐步出现编辑器与笔记，修了两版仍未达到预期。经讨论，用户确认需求如下：

- 服务更新后的首次进入继续用纸页动画替代数秒空白。
- 同一版本退出后重新打开，直接呈现完整界面（导航、含日历与标签的侧栏、编辑器、笔记列表），中间不出现加载动画，也不出现列表逐步加载。
- 用户指出加启动动画之前的版本重开时没有空白感。经解释后确认以该原始版本的实际时序为基准：日常重开期间只显示与界面一致的背景色，完整界面一步出现；超过 2 秒或失败时才显示纸页动画和恢复入口。

本次未制作 ImageGen 设计预览：目标就是用户截图中的现有完整界面，没有新增或改动布局、颜色与组件，只移除过渡期的灰色框架和逐步加载。

### 调查

在本机分别构建加启动动画之前的原始版本 `52b94720` 和修复版本的生产产物，使用独立的可丢弃数据，在 Chrome 网络延迟模拟下逐帧比较：

- 原始版本重开时根节点为空、只露出背景色，随后约 0.15 秒内依次补齐侧栏、编辑器、笔记和标签。“一打开就是完整界面”的体感来自这些变化集中发生，且都在纯背景之后。
- 上一版在静态层先画灰色框架并提前交接，React 再依次提交导航、侧栏、页面占位、编辑器和列表，于是出现录屏里约一秒的多段变化。
- 首页局部 Suspense 每次启动都会先提交占位。React 19.2 对已提交过占位的边界有 300ms 揭示节流（`FALLBACK_THROTTLE_MS`），同步渲染时即使首页模块已预加载也会先挂起一次，首页和列表请求因此推迟约 290ms：60ms 延迟下 ListMemos 在 566ms 才发出，修复后为 251ms。
- 启动期根节点使用 `visibility: hidden`，揭开时带 `transition-all` 的侧栏容器、编辑器和按钮会晚一帧出现；有界面 Chrome 的录像里能看到只有导航和卡片的半成品帧。
- 日历在统计数据返回前已挂载。当天格子的计数变化与揭开发生在同一帧时，150ms 的颜色过渡在揭开后仍然可见。

### 实现

- 静态层：日常重开（同版成功记录，且为笔记或待办入口）只保留背景色，不显示框架、文字或动画；2 秒仍未就绪时改为纸页动画，12 秒超时或样式加载失败时显示恢复入口。首次启动、新版本和存储不可用时仍显示纸页动画。移除灰色框架和 `memos:startup-shell-ready` 提前交接。
- 首页：`StartupReady` 等到完整的用户与实例设置、侧栏统计（由 `MainLayout` 通过上下文提供加载状态），以及第一页笔记、空状态或错误都可显示后，才通知揭开。站内切换页面的行为不变。
- 首页模块已预加载时，`FeedRoute` 直接渲染真实组件，不经过 lazy 挂起，从而避开 Suspense 节流；模块未就绪时保留原有占位和 12 秒重试。
- 启动层不再隐藏根节点，只靠不透明遮罩覆盖。遮罩期间禁用根节点内的 CSS 过渡，揭开前强制结算一次样式，避免同帧到达的数据在揭开后继续渐变。根节点仍保持 `inert`、`aria-hidden`、固定定位和裁剪。
- 未改变认证、令牌、请求业务规则、缓存、Service Worker、部署或发布流程，也没有人为延迟。
