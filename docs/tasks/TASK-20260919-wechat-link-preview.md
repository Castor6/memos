## 背景与目标

真实公众号链接默认请求可能返回验证码页面，增加 User-Agent、Accept-Language、Referer 后可取得文章 HTML。现有解析器误把空 `<title></title>` 的结束标签名读成 `title`，并覆盖此前的正确 `og:title`。用户要求使用 Go 对微信链接采用专用请求方式，其他链接仍使用原请求方式；无法取得有效标题时保留普通链接，并查看修改后的本地预览。

## 验收标准

- [x] 仅精确匹配 `mp.weixin.qq.com` 的公众号请求添加三个请求头；非微信站点、相似域名不添加；重定向重新判定目标站点。
- [x] 空 title 不产生字面量 `title`；非空 og:title 优先，顺序不影响结果；正常网页标题仍能回退读取。
- [x] 抓取失败、非成功 HTTP、无标题或已知微信通用标题时显示普通链接；标题正常时显示卡片。
- [x] 用真实公众号和掘金链接验证抓取与前端卡片；受控失败场景在单元测试中模拟。
- [x] 在独立 worktree 完成后端/前端检查和本地浏览器验证，不修改另一个会话的工作区。

## 讨论结论

不引入 Python、浏览器自动化抓取或新依赖。公众号采用 Go HTTP 请求头适配，复用现有 HTML 元数据解析、5 秒超时、512 KiB 读取上限、HTTP(S)/内网地址与重定向检查。视频号并非公众号文章，保留原请求方式，但已知的通用标题不生成卡片。

## 实现结果

- `GetHTMLMeta` 对公众号域名添加已实测的 User-Agent、Accept-Language、Referer；跨域重定向移除专用请求头，普通站点继续使用默认请求方式。
- 只接受 2xx HTML 响应；解析 `<title>` 时只读取文本 Token，并优先保留非空 Open Graph 标题，修复空标签覆盖标题的问题。
- 公众号的 `title` / `微信公众平台`、视频号的 `title` / `视频号` 属于已知通用标题，在对应域名清空，避免误作文章名称。
- `LinkMetadataCard` 只有在请求成功且标题非空时显示卡片；仅有摘要或图片仍保留普通链接；封面加载失败仍可保留标题。
- Markdown 的卡片触发规则、懒加载和预览开关没有变化：顶层段落只有一个链接，且链接文字等于 URL。行末双空格只是硬换行，不保证生成卡片。
- 使用根目录 Changesets CLI 新增中文 patch 说明，没有改变依赖、版本号或生成文件。
