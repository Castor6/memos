# TASK-20261018-memo-context-menu-dismiss：笔记右键菜单关闭时跳位

- 记录日期：2026-10-18
- 模块与关键词：MemoActionMenu、右键菜单、退出动画、虚拟锚点
- 维护归属：本次排查会话，分支 `fix/memo-context-menu-dismiss`
- 关联任务：[笔记右键入口](TASK-20260920-memos-todo-alignment.md)

## 背景与目标

用户提供录屏：笔记正文右键打开菜单，再左键点击其它区域，菜单在卡片右上角短暂出现后消失。要求切回主分支并拉取后排查。

主工作区已切换到 `main` 并快进至 `2bf50f26`；修改在独立 worktree 进行。录屏逐帧检查确认关闭阶段发生跳位，持续约 150 毫秒。

## 验收标准

- [x] 右键菜单点击外部或按 Esc 关闭时在原鼠标位置淡出，不跳到三点按钮。
- [x] 关闭后通过三点按钮重新打开仍按按钮定位，再次右键按新鼠标位置定位。
- [x] 完成定向回归、前端检查及桌面和两种手机高度的浏览器验证。

## 排查与方案

- 原代码在 `onOpenChange(false)` 立即清空 `contextMenuPosition`，虚拟锚点变成 `undefined`，对齐从 `start` 切为 `end`；此时共享菜单的 150ms 退出动画仍在运行，剩余内容重新定位到三点按钮。
- 保留关闭中的虚拟锚点直到菜单动画结束；菜单打开状态立即关闭，避免用定时器延迟关闭或修改共享动画。
- Browser plugin not available；依据仓库要求使用 `cua_repl` 提供的 Codex 内置浏览器验证本地可丢弃数据。

## 实现结果

- `MemoActionMenu.tsx` 在关闭事件中保存鼠标位置，在 Base UI 的 `onOpenChangeComplete(false)` 释放；通过三点按钮打开时也清掉旧位置。菜单关闭状态即时生效，共享的 150ms 动画保持原样。
- 回归测试为 jsdom 提供可见视口，并用可控动画 Promise 保持退出阶段，验证外部点击和 Esc 两条路径中的实际定位不变、动画完成后卸载、三点按钮重新定位和新右键坐标生效。
- 根目录 Changesets CLI 创建 `memos-personal` 的中文 patch 说明，扩展无变更。
